# OpenBot 上游变化影响分析

状态：已产出首轮固定材料分析，见 [eval 012](../../../evals/012-upstream-impact.md)
及其报告；维护者已采用入口建议，缺材料场景与 Bot 运行验收待完成。尚未交付持续观察能力。

以上状态仅指本 spec 的固定材料首轮验收。后续用户已选择只看 GitHub 上游与 fork，
持续观察的实现与独立现场验收见 [upstream observation](upstream-observation.md) 和
[eval 016](../../../evals/016-upstream-observation.md)，不读取宿主工作区。

## 目标

落实[产品目标](../../product.md)中的持续性委托：替 fork 维护者关注 OpenBot 上游，
结合本地差异筛选变化，交付有出处、能支持下一步决定的影响分析。
先验证一次完整分析是否有用，再接持续观察；阶段安排不代表已经交付。

## 首轮范围

用户手动发起一次分析，指定或确认上游提交区间与本地比较版本。
分析输入固定为上游仓库、起止 commit、本地 commit 与相关本地差异、产品目标。
若包含未提交改动，单独记录其快照，不能仅用 HEAD 标识输入。

输出保留输入版本与来源，列出值得跟进的变化、相关本地文件、影响依据、
建议跟进／暂缓／忽略的理由和一个具体下一步。没有值得跟进的变化也是有效结果。
无法获取或核实的材料明确标为缺失，不能当作无影响；上游文本作为不可信数据处理。

首轮允许人工提供固定材料，以便把分析质量与自动采集能力分别验证。
通过 Bot 采集仓库或文件时，必须使用现有获准工具和网关。

## 不做事项

首轮不增加自动调度、跨轮去重、通用恢复 journal、自动改代码、提交、合并或对外发布。
不新增界面、渠道、权限模型或独立队列，不替换 Intelligence，不扩大信息源。

## 实现导航与约束

- 当前架构与复用边界见[设计](../../design.md)；首轮先检查已有对话、工具与成果能力，
  确认缺口后再选择窄扩展点，不预设新增专用工具。
- 后续持续观察先检查 `server/src/responsibilities/` 的 store、engine、wiring 和 tools，
  以及 `server/src/routines/` 的调度与 runner；复用既有队列、delivery 与审计。
- 恢复与重试约束见[任务领域](../tasks.md)，消息交付见[消息领域](../messaging.md)。
  保存处理进度不自动等于步骤恢复；离线补查不能假设 routines 会回放错过的窗口。
- owner、initiator、grants 延续原委托，动作经过策略、审计与执行网关。
- 本 spec 不宣称已完成代码调用链盘点；开始实现时检查入口、调用方、失败路径与现有测试。

## 首轮验收与决定证据

实现前在 `evals/` 增加对应场景，固定真实提交区间、本地快照与人工核对依据。
至少包含一项与本地改动有关的变化和一项无关变化；保留材料，使结果可重复核对。

验收检查：

1. 报告引用的 commit、路径和变化在固定材料中真实存在，关键影响结论有对应依据。
2. 人工预先标出的重要相关变化得到处理；无关变化未被编造成本地影响。
3. 每项跟进建议能支持明确决定，维护者记录采用、驳回及理由；
   首次验收记录是否至少一项建议被采用，不能仅凭 Bot 自评有用。
4. 材料缺失时保留未知，不输出“全部检查完成”或“没有影响”的错误结论。
5. 保存成果文件或实际回复；若发生工具调用，同时核对审计中的调用、决策与结果。
   记录本轮模型、调用成本（可获取时）和耗时，尚不设置未经测量的阈值。

首轮完成须有上述 eval 的实际结果与证据，以及[验证流程](../verification.md)要求的检查。
没有实际运行的验收保持未验收，不能把固定材料分析通过扩大为持续委托通过。

## 后续顺序

   再定义持久进度与通知去重验收，接入已有调度机制。
